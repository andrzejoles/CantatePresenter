Podsumowanie

Mocny produkt, kruche fundamenty

Funkcjonalnie aplikacja jest bogata i przemyślana pod kątem operatora: podgląd w proporcjach ekranu, Auto-Fit, wyszukiwanie z polskimi znakami, import z Holyrics. Największe ryzyko leży w warstwie danych i obsłudze klawiatury, czyli tam, gdzie błąd w trakcie nabożeństwa jest najbardziej odczuwalny.

Pięć rzeczy do naprawy w pierwszej kolejności:

  1. Biblioteka pieśni może zostać nadpisana przykładami przy każdym błędzie odczytu songs.json (K1).
  2. Dane leżą obok pliku .app, więc po instalacji w /Applications biblioteka „znika”, a zapis może się po cichu nie udawać (K2).
  3. Esc w dowolnym oknie dialogowym gasi projektor, a Enter w Ustawieniach uruchamia prezentację (K3).
  4. Brak menu Edycja: w edytorze pieśni nie działa ⌘C / ⌘V / ⌘Z (W1).
  5. Integracja z Dyskiem Google nie może działać: Google wyłączył użyty przepływ OAuth, a token nie jest odświeżany; automatyczny backup przy zamykaniu blokuje się sam (W2, W3).
Co jest dobre

Mocne strony

  • Zero zależności zewnętrznychCzysty SwiftPM, szybki build, mała powierzchnia ataku.
  • Auto-Fit przez wyszukiwanie binarneAutoFitEngine sprawdza i szerokość pojedynczych słów, i wysokość akapitu.
  • Wierny podglądPresentationSlidePreviewCanvas liczy czcionkę dla rozdzielczości projektora i skaluje ją proporcjonalnie.
  • Polskie wyszukiwanieFolding diakrytyków z osobną obsługą „ł”, sortowanie z polską kolacją.
  • Własny parser Java ObjectStreamImport .mufl bez JVM to nietrywialne i trafne rozwiązanie.
  • Tolerancyjny dekoder ustawieńAppSettings.init(from:) z wartościami domyślnymi to wzorzec, który warto rozszerzyć na modele pieśni.

K1

Utrata biblioteki przy błędzie dekodowania songs.json

krytyczna
Services/DataStore.swift:91–103 · Models/Song.swift:3 (brak własnego dekodera)
Problem

loadSongs() nie odróżnia „pliku nie ma” od „pliku nie da się odczytać”. Każdy błąd JSONDecoder (uszkodzony plik, ręczna edycja, a przede wszystkim dodanie nowego pola do Song, który używa syntezowanego Codable) kończy się wczytaniem SampleSongs i natychmiastowym saveSongs(). To samo dotyczy planów w loadPlans().

Skutek

Pierwsza aktualizacja aplikacji, która doda np. pole ccliNumber, nadpisze całą bibliotekę użytkownika kilkoma przykładowymi pieśniami. Nie ma kopii, z której dałoby się to odzyskać.

Proponowana zmiana
  • Rozdzielić przypadki: brak pliku → przykłady; błąd odczytu → przenieść plik do songs.corrupt-<data>.json, pokazać alert i nie zapisywać.
  • Dodać do Song, SongSlide i ServicePlan dekodery z decodeIfPresent (jak w AppSettings) oraz pole schemaVersion w pliku.
  • Przed każdym zapisem trzymać rotacyjną kopię (np. 5 ostatnich wersji).
public func loadSongs() {
    guard FileManager.default.fileExists(atPath: songsFileURL.path) else {
        songs = SampleSongs.loadDefaults(); saveSongs(); return
    }
    do {
        let data = try Data(contentsOf: songsFileURL)
        songs = try decoder.decode([Song].self, from: data)
    } catch {
        let quarantine = songsFileURL.deletingPathExtension()
            .appendingPathExtension("corrupt-\(Int(Date().timeIntervalSince1970)).json")
        try? FileManager.default.copyItem(at: songsFileURL, to: quarantine)
        loadError = .songsUnreadable(error, quarantine)   // pokazywane w UI
        isPersistenceLocked = true                         // saveSongs() nic nie robi
    }
}
K2

Dane zapisywane obok pakietu .app

krytyczna
Services/DataStore.swift:29–42 · LocalizationService.swift:396 · BackupService.swift:48 · StandbyWebView.swift:387 · AppDelegate.swift:95 · AppInstallerService.swift:385
Problem

Katalog data/ jest wyznaczany jako bundleURL.deletingLastPathComponent(), czyli folder, w którym leży aplikacja. Ta sama logika jest skopiowana w pięciu miejscach.

Skutek
  • Wbudowany instalator kopiuje aplikację do /Applications. Po restarcie dane są szukane w /Applications/data, więc użytkownik widzi pustą bibliotekę z przykładami; jego pieśni zostają w starym folderze.
  • Konto bez uprawnień administratora nie może pisać w /Applications; uruchomienie z DMG (tylko do odczytu) też nie zapisze danych. Wszystkie zapisy idą przez try?, więc błąd jest niewidoczny.
  • Przy swift run dane zależą od bieżącego katalogu terminala.
Proponowana zmiana

Jeden typ AppPaths wskazujący na ~/Library/Application Support/CantatePresenter, plus jednorazowa migracja ze starej lokalizacji. Zasoby tylko do odczytu (domyślny standby.html, loga) przenieść do zasobów pakietu SwiftPM.

    }()
    static var songs: URL { dataDirectory.appendingPathComponent("songs.json") }

    /// Kopiuje dane ze starego „data/” obok .app, jeśli nowa lokalizacja jest pusta.
    static func migrateLegacyDataIfNeeded() { … }
}
K3

Globalne przechwytywanie Esc, Enter, Spacji i strzałek

krytyczna
Views/MainView.swift:233–316 · Services/ScreenManager.swift:146–157
Problem

Oba lokalne monitory NSEvent działają w całej aplikacji, niezależnie od tego, które okno jest aktywne. Jedyny filtr to „czy fokus jest w polu tekstowym”. Monitor z MainView jest dodawany w onAppear i nigdy usuwany (token nie jest zapamiętywany).

Skutek
  • Operator otwiera Ustawienia w trakcie pieśni i naciska Esc, żeby je zamknąć: monitor ScreenManager zamyka okno projekcji, a monitor MainView wywołuje stopLive(). Arkusz zostaje otwarty, projektor gaśnie.
  • Enter na przełączniku w arkuszu Ustawień uruchamia projekcję zaznaczonej pieśni (startPresentationKey = 36).
  • Strzałki na liście pieśni zmieniają slajd zamiast zaznaczenia, a Spacja na przycisku w arkuszu przełącza slajd.
Proponowana zmiana

Jeden KeyboardRouter rejestrowany raz (w AppDelegate), działający tylko dla okna głównego bez otwartego arkusza oraz dla okna projekcji. Esc w oknie głównym z arkuszem musi trafić do arkusza.

monitor = NSEvent.addLocalMonitorForEvents(matching: .keyDown) { event in
    guard let key = NSApp.keyWindow,
          key.attachedSheet == nil,
          key === AppDelegate.shared?.mainWindow || key is PresentationWindow,
          !(key.firstResponder is NSText) else { return event }
    return router.handle(event) ? nil : event
}

W3

Dysk Google: wyłączony przepływ OAuth i brak odświeżania tokenu

wysoka
Services/GoogleDriveService.swift:43, 67, 111–119, 163
Problem
  • redirect_uri = urn:ietf:wg:oauth:2.0:oob to przepływ „out-of-band”, który Google zablokował dla nowych i istniejących klientów w latach 2022–2023. Logowanie zakończy się błędem invalid_request.
  • getValidAccessToken() zwraca zapisany accessToken, jeśli nie jest pusty, bez sprawdzania ważności. Token wygasa po ok. godzinie, potem każde żądanie dostaje 401, a odświeżenie nie jest próbowane.
  • Nazwa folderu jest wklejana do zapytania q bez escapowania apostrofu.
  • downloadBackupFromDrive używa nazwy pliku z Dysku jako ścieżki w katalogu tymczasowym.
Proponowana zmiana
  • Przepływ dla aplikacji desktopowych: przekierowanie na loopback (http://127.0.0.1:<port>) z PKCE, otwierane przez ASWebAuthenticationSession lub przeglądarkę systemową. Przy PKCE sekret klienta nie musi być wpisywany przez użytkownika.
  • Przechowywać expiresAt; odświeżać token przed wygaśnięciem i ponawiać żądanie raz po 401.
  • Escapować ' w zapytaniu (\'), plik tymczasowy nazywać UUID.

W6

Deserializer .mufl: awaria lub zawieszenie na uszkodzonym pliku

wysoka
Services/HolyricsJavaDeserializer.swift:160–161, 186, 214, 383–391
Problem
  • Linia 186: ref - BASE_WIRE_HANDLE na UInt32. Dla wartości mniejszej niż 0x7E0000 Swift zatrzymuje program (przepełnienie arytmetyczne).
  • Linie 383–391: długość tablicy z pliku (do ~4,3 mld) trafia do reserveCapacity i pętli. Po końcu danych readContent() zwraca nil, więc pętla kręci się miliardy razy.

Skutek

Obcięty lub uszkodzony plik eksportu (np. przerwane pobieranie) zamyka aplikację albo zawiesza import.

Proponowana zmiana
guard ref >= Self.BASE_WIRE_HANDLE else { throw DeserializationError.invalidReference(ref) }
let handleIndex = Int(ref - Self.BASE_WIRE_HANDLE)

let arrLen = Int(readUInt32())
guard arrLen <= data.count - pos else { throw DeserializationError.prematureEndOfData(pos) }

guard depth < 64 else { throw DeserializationError.tooDeep }

Do tego testy na plikach z data/holyrics_samples oraz ich obciętych i losowo uszkodzonych wariantach.

W7

Błędna transpozycja akordów

wysoka
Services/GuitarChordsService.swift:141–206, 89–138
Problem

Wzorzec \b([A-H][#b]?)…\b sprawdziłem na przykładach:

  • Akordy molowe w notacji polskiej (a, e, d) nie pasują do [A-H], więc nie są transponowane, choć transposeRoot obsługuje małe litery.
  • Krzyżyk gubi granicę słowa: w "F# G" dopasowuje się samo F. Po transpozycji o +1 wynik to F##.
  • Bemole (Bb, Eb) i polskie B (= B♭) nie występują w skali krzyżykowej i zostają bez zmian.
  • extractChordsAndCleanLyrics wkłada do arkusza akordów także linie tekstu, więc słowo „A” na początku wersu zostaje „przetransponowane”.
Proponowana zmiana

Tokenizować tylko linie rozpoznane jako akordowe; wzorzec z jawnymi granicami i małymi literami; mapowanie bemoli i polskiego B/H na indeks półtonu; wybór zapisu krzyżykowego lub bemolowego według tonacji docelowej. Testy jednostkowe dla wszystkich 12 przesunięć.

(?<![\p{L}#])([A-Ha-h](?:#|b|is|es)?)(m|maj7?|min|dim|sus[24]?|add9)?(\d{0,2})(?:/([A-Ha-h](?:#|b)?))?(?![\p{L}#])

Średnie

Błędy brzegowe, wydajność i spójność.

S1

Po odłączeniu projektora projekcja zasłania ekran operatora

średnia
Services/ScreenManager.swift:72–82, 196–201
Problem

Ekran docelowy jest zapisywany jako indeks w NSScreen.screens. Gdy kabel HDMI się poluzuje, repositionPresentationWindowIfNeeded przenosi okno na screens[0], czyli laptop operatora, na poziomie .screenSaver. Po ponownym podłączeniu kolejność ekranów może być inna.

Proponowana zmiana

Zapamiętywać CGDirectDisplayID (z deviceDescription["NSScreenNumber"]) i nazwę. Po zniknięciu ekranu ukryć okno projekcji, pokazać komunikat i wrócić automatycznie, gdy ten sam ekran się pojawi.

S2

Wydajność: jeden ObservableObject i ciężkie obliczenia w body

średnia
Services/DataStore.swift:6–22 · Views/SongListView.swift:50–80 · Models/Song.swift:62–88 · PresentationContentView.swift:465 · PresentationSlidePreviewCanvas.swift:393
Problem
  • Każda zmiana slajdu (activeSlideIndex) unieważnia wszystkie widoki obserwujące DataStore, w tym listę pieśni.
  • filteredSongs przy każdym przerysowaniu filtruje i sortuje całą bibliotekę, a matches wykonuje folding całego tekstu każdej pieśni. Przy ~900 pieśniach po imporcie z Holyrics to zauważalne opóźnienie przy każdym naciśnięciu klawisza.

Proponowana zmiana

Rozdzielić stan na LibraryStore i LiveState oraz przejść na makro @Observable (dostępne od macOS 14, czyli minimalnej wersji projektu), które śledzi pojedyncze właściwości. Złożone pola wyszukiwania liczyć raz przy zapisie pieśni. Wynik Auto-Fit zapamiętywać w słowniku z kluczem (tekst, rozmiar, ustawienia czcionki).

Poza listą błędów

Co jeszcze bym ulepszył

Poniższe punkty nie są błędami, ale wyraźnie podniosą niezawodność i wygodę rozwoju.

Architektura

  • Zamiast singletonów (DataStore.shared, ScreenManager.shared) wstrzykiwać zależności przez środowisko SwiftUI. Bez tego kodu nie da się sensownie testować.
  • Warstwa Repository odpowiedzialna za zapis, migracje schematu i kopie; widoki nie powinny znać plików JSON.
  • Przy rosnącej bibliotece rozważyć SQLite (np. GRDB z FTS5 do wyszukiwania pełnotekstowego) albo SwiftData.
  • Tryb języka Swift 6 ze ścisłą współbieżnością: usunie dziesiątki ręcznych Task { @MainActor in … } i wyłapie błędy jak W2 na etapie kompilacji.

Testy

  • Projekt nie ma żadnego celu testowego. Pierwsze testy (Swift Testing): Song.parseLyrics, transpose, deserializer .mufl na plikach z data/holyrics_samples, wykrywanie kodowania, deduplikacja, zgodność wstecz dekoderów modeli.
  • Testy migawkowe SlideRenderer w kilku rozdzielczościach, żeby Auto-Fit nie zaczął obcinać tekstu po zmianie.

CI i dystrybucja

  • GitHub Actions na macos-14: swift build, swift test, SwiftLint i SwiftFormat przy każdym PR.
  • Podpis Developer ID i notaryzacja (notarytool). Obecny podpis ad-hoc sprawia, że Gatekeeper blokuje aplikację na innych Macach.
  • Automatyczne aktualizacje przez Sparkle; wersja i build ustawiane z tagu git.
  • Projekt Xcode lub Package.swift z zasobami (resources: [.process("Resources")]) zamiast ręcznie składanego pakietu .app.

Niezawodność na żywo

  • Cofanie (UndoManager) dla usuwania i edycji pieśni oraz planów; potwierdzenie usunięcia pieśni użytej w planie.
  • Klawisz „panika” natychmiast wygaszający ekran, działający zawsze, także przy otwartym arkuszu.
  • Wskaźnik w oknie głównym, gdy projektor zniknie (S1), oraz automatyczny powrót.
  • Autozapis szkicu w edytorze pieśni.

Funkcje

  • Monitor sceniczny dla muzyków: drugi ekran z bieżącym i następnym slajdem oraz akordami.
  • Zdalne sterowanie z telefonu (lokalny serwer WWW z Bonjour), np. dla lidera uwielbienia.
  • Motywy per pieśń: tło (obraz, wideo), krój, kolor; płynne przejścia między slajdami.
  • Wyjście NDI lub Syphon dla transmisji online.
  • Eksport i import OpenLyrics, OpenSong, ProPresenter; raportowanie CCLI.
  • Kolejność sekcji (np. Z1 R Z2 R) bez powielania tekstu refrenu.

Dostępność i UI

  • Etykiety VoiceOver dla przycisków z samą ikoną (np. gearshape, stop.fill).
  • Ostrzeżenie o zbyt niskim kontraście kolorów tekstu i tła projekcji w Ustawieniach.
  • Rzeczywisty postęp importu zamiast wartości ustawianych na sztywno (0,35, 0,65).

Dokumentacja

  • README: usunąć ścieżki lokalne i nazwę „Holyrics Mac”; dodać krótki opis architektury, CONTRIBUTING.md, CHANGELOG.md i licencję.
  • Opis formatu plików danych i polityki migracji schematu.
